# 반복 후보 추천 — 통합 준비 PASS

2026-10-23. 기준 `feature/release-integration` / `3adb0e2`, 작업 브랜치 `feature/rolling-candidates`, 격리 worktree `/private/tmp/banguseok-rolling-candidates`.

## 구현

- 기존 부문별12편/6+6 페이지를 제거하고, 실제 TMDB로 재확인한66편 전체에서 한 화면에 고유6편을 가중 비복원 추출한다. `다른 후보작 둘러보기 ↻`는 횟수 제한 없이 동작한다. 이미 본 영화는 다시 나올 수 있지만 직전과 같은6편 집합이면 풀 외부1편으로 교체한다. 과거 전체 노출 이력은 누적하지 않는다.
- 부문별 기존 편집 seed와 설문 답변으로1~1.8의 약한 가중치를 준다. 모든 후보는 양수확률이다. q1은 grand/dissent, q2는 sorry, q3는 once, q4는 lifetime, q5는 rescue의 seed 관련성에 최대0.2를 더한다. q6는 낮은 관람량의 familiar/높은 관람량의 discovery seed에0.2를 더하는 편집 가설이다. 실제 취향·작품 수준·흥행 순위·타인의 반응을 추정하는 모델은 아니다.
- 후보6개만 `candidate_order`에 저장하고 `candidate_page`는 제거했다. 구형12편 초안은 보고 있던 페이지6개로 이전한다. UUID·설문·수상작·대기작·시각과 기존 draft/server version은 유지한다. 후보 변화는 저장 payload나 결과 계산에 들어가지 않는다. 풀 밖 검색작도 그대로 유지한다.
- 설문 완료 시 답변을 반영해 초기 후보를 정하고, 재추출은 최신 초안의 설문을 읽어 후보 필드만 바꾼다. 이미 확정한 작품은 재추출·뒤로·부문 이동·복원으로 초기화하지 않는다.
- D+E의6카드·크레용·검색·확정 UI를 유지했다. 최초 메타데이터 확인 중 상태를 표시하며, 실패/빈 항목/429/503에는 안내와 명시 재시도를 제공한다. 검증된 metadata가 기본값이므로 네트워크 실패 중에도 카드 선택·확정이 가능하다. 검색작은 기존 detail 확인을 유지한다.

## 통신과 보안 경계

`candidate-movies.ts`는2026-10-22 실제 TMDB 검증 결과의 공개 필드66개뿐이다(약15.4KB 소스). 제목·개봉연도·원제·포스터 경로는 같은 TMDB 영화 객체에서 왔다. 포스터를 합성하거나 다른 작품의 이미지로 대체하지 않는다. 이미지 실패 시 기존 ‘포스터 없음’ 타일을 사용한다.

반복 추출은 브라우저에서 처리하므로 **추천 버튼72회에 추가 앱 API0회·TMDB0회**다. 최신 정보 확인은 부문 최초 진입/명시 재시도의 기존 candidates API를 사용하며, 성공 결과를 같은 탭의 부문 재방문에서 재사용한다. 콜드 batch1회는 최대6개 상세 조회, 이후 기존 서버24시간 상세 캐시가 적용된다. 전체 페이지 reload나 새 탭은 메모리 캐시를 초기화한다. 검색/검색작 상세 확인·메타데이터 재시도는 별도 API 호출이며 기존 M5 요청·단위 예산을 소비한다. 자동 재시도/폴링은 없다.

후보 풀은 유한한66편이다. 무제한은 재추출 횟수이며 매번 미노출 작품6편을 보장하지 않는다. 최신 TMDB 변경으로 snapshot이 오래될 수 있어 주기적으로 기존 `verify:m2:catalog`로 재검증하고 public snapshot 변경을 검토해야 한다. 실제 서버 저장은 여전히 실제 TMDB 상세를 검증하므로 TMDB 장애 중 DB 저장 성공을 보장하지 않는다.

M5 보안/Origin/CAPTCHA/503·RLS·Supabase schema·M6 PNG·검색 API 구현은 변경하지 않았다. 로컬 후보 선정 가능 여부와 운영 저장/게시 가능 여부는 별개다. Production이나 Preview를 배포·설정 변경하지 않았고 원격 계정/콘텐츠/증명도 만들지 않았다. 기존 통합 E2E는3adb0e2의 결과이며 이 새 소스의 원격 배포 증명이 아니다.
