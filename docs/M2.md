# M2 — 후보 추천·영화 검색·수상작 선정

2026-10-21 · 사용자 지시에 따라 PRD/SCREEN_CONTENT/CODEX_STEPS v1.1 기준으로 구현했다. 부문·편집 후보·설문·점수 규칙은 변경하지 않았다. 선택 방식은 사용자 비교 시험 전의 **임시 B 확정 버튼 + 2열**이다.

## 실행과 URL

```sh
npm run dev
npm test
npm run lint
npm run typecheck
npm run build
npm run verify:m1
npm run verify:m2:catalog
npm run verify:m2:http
npm run verify:m2:browser
npm run verify:g2:secrets
```

- `http://localhost:3000/` → 설문 → 시상 부문 목록
- `http://localhost:3000/create/awards`: 고정 순서 6부문과 현재 선정/미시상/미방문 상태
- `http://localhost:3000/create/awards/grand`: 대상 후보 화면. 나머지는 lifetime/sorry/once/dissent/rescue
- `http://localhost:3000/create/review`: 최소 3부문 선정 후의 로컬 완료 화면. 결과 생성/DB 저장 버튼은 아직 연결하지 않는다.

새 프로필이면 설문을 먼저 진행한다. 건너뛰기도 가능하다. 기존 M1 초안은 같은 저장 키에서 UUID·설문·시각을 유지한 채 M2 필드를 추가한다. 실제 환경변수 값은 코드/문서/증거 파일에 넣지 않았다. 추가 의존성·환경변수·SQL migration은 없다.

브라우저 검증 스크립트는 이 Mac의 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`을 사용한다. 별도 임시 프로필과 CDP로 360×800 headless Chrome을 실행하며 사용자 브라우저의 저장소를 건드리지 않는다. 종료 시 임시 프로필과 자신이 실행한 프로세스를 정리한다. 다른 OS에서는 실행 경로 조정이 필요하다.

## 구현한 규칙

- grand → lifetime → sorry → once → dissent → rescue. 문서의 이름·설명·그룹별 4편을 그대로 사용한다.
- 새 초안에서 그룹별 Fisher–Yates 후 앞/뒤 2편을 각각 섞어 6장씩 두 페이지를 만든다. 다른 후보 보기 → 처음 후보 다시 보기로 전체 12편을 순환하며 중복 복제/무한 추천을 하지 않는다.
- 카드 탭은 pending, ‘이 작품에 수여’가 확정이다. 확정 후 다음 미선정·미건너뜀 부문으로 이동한다. 기존 수상작 변경은 확정 후 목록으로 돌아온다.
- 같은 영화의 복수 부문 수상을 허용하고 대상은 필수가 아니다. 3개의 서로 다른 부문이면 바로 완료 화면에 갈 수 있다.
- 명시적 ‘목록으로’는 해당 부문의 pending만 취소한다. 새로고침·브라우저 이동은 pending도 보존한다. 페이지/검색 전환도 pending을 보존한다. 확정작이 있는 부문을 건너뛸 때는 제거 확인을 표시한다.
- 후보 배열·page·pending·확정작·건너뛴 부문·현재 부문/화면을 기존 로컬 초안에 저장한다. 잘못된 후보 배열만 복구하며 설문과 유효한 수상작은 유지한다. 복구/승격 결과는 즉시 저장해 재로딩 때 다시 섞이지 않게 했다.
- 모바일 2열·2:3 포스터·제목/연도·색 외의 선택 표시·전체 제목 접근 이름과 하단 선택 영역을 제공한다. 열 수는 `.poster-grid`의 `--poster-columns`로 분리했다.
- 후보 정보 실패는 해당 슬롯을 ‘정보 없음’으로 유지한다. 다른 페이지 작품을 복제하지 않는다. 포스터만 없거나 이미지 로드에 실패하면 제목 타일을 표시하며 선정은 계속 가능하다.
- 직접 검색은 한국어/영어, trim 후 1~100자, IME 종료 후 350ms debounce, 요청 취소/오래된 응답 무시, 최대 20개×5페이지, 더 보기 중복 ID 제거를 사용한다. 검색 결과에 제목·연도·원제를 표시한다. 선택 시 실제 상세를 다시 확인하고 pending으로 보낸다.

검색은 기존 서버 전용 TMDB 클라이언트를 재사용한다. ko-KR/adult 제외/5초 제한/안전한 포스터 경로/오류 응답 계약은 그대로다. 공식 검색 API는 원제·번역·대체 제목 검색을 지원한다. [TMDB 검색 API](https://developer.themoviedb.org/reference/search-movie)

## 제품 경로와 운영 제한

`POST /api/catalog/movies`를 별도로 추가했다. 기존 G2 `/api/movies/*`의 development 전용 조건은 변경하지 않았다.

M2 경로는 loopback Host + 같은 Origin, JSON 1KB 이하, action/ID/query/page, 6개의 고유한 편집 후보 ID를 서버에서 검증한다. 로컬 단일 프로세스 한도는 분당 60이며 캐시되지 않은 batch 상세 호출도 비용에 포함한다. 429는 Retry-After 60초를 제공한다. 검색 10분/상세 24시간의 제한된 메모리 캐시는 공개 영화 메타데이터만 저장한다. 응답은 private/no-store다. 브라우저에는 TMDB 토큰이 전달되지 않는다.

**운영 관리형 요청 보호가 확인되지 않아 production에서는 이 경로가 항상 503 PROTECTION_REQUIRED로 닫힌다.** 메모리 제한을 Vercel 전체/IP별 제한이라고 주장하지 않는다. 공개 배포 전 신뢰할 수 있는 플랫폼 IP 기반 검색+상세 60회/분/IP와 비용 한도를 확인하고, production 게이트 변경 및 검증이 필요하다. 미지원이면 PRD 8장의 원자적 bucket 대체안을 별도 작업으로 적용한다. 환경변수 하나로 보호 없이 우회하는 옵션은 만들지 않았다.

## 실제 TMDB 검증

`verify:m2:catalog`: **고유 영화 66편 / 부문 슬롯 72개** 상세 조회 통과. 실제 ID·한국어/원제·개봉 연도·포스터 경로/URL은 [catalog-verified.json](../artifacts/m2/catalog-verified.json)에 있다. 편집 목록과 그룹은 단위 테스트에서 문서 원문과 비교한다.

실제 조회 중 두 식별 차이를 확인했다.

- ‘반딧불이의 묘(1988)’는 동명의 2005년 실사판 검색 결과(ID 76826)를 채택하지 않았다. 1988년 애니메이션 ID **12477**을 상세 검증하고 카탈로그/회귀 테스트에 고정했다.
- ‘언더 더 스킨’은 편집 목록의 2013년을 보존한다. 실제 ID **97370**의 TMDB release_year는 **2014**이며 화면은 실제 조회 연도를 사용한다. 명세에도 목록 연도는 식별용 초안으로 기재되어 있어 후보 작품/규칙 변경은 아니다.

`verify:m2:http`: **8그룹 통과**. 실제 기생충(496243)/Inception(27205) 검색, 기생충 상세·포스터, 포스터 없는 Untitled(1647338), 잘못된 ID 400/없는 ID 404, 실제 0건·빈 검색어 400, 다른 Origin 403, M2 응답의 실제 토큰 문자열 미검출을 확인했다. 실제 인증 실패·TMDB 429·인터넷 단절을 일부러 유발하지 않았다.

## 테스트와 브라우저 증거

| 실행 | 결과 |
| --- | --- |
| `npm test` | **59/59 통과**: 기존 G1/G2/G3/M1 45건 + M2 14건 |
| typecheck / lint / build | 모두 통과 |
| `verify:m1` | 기존 3경로 HTTP 검사 통과. 시상 페이지의 변경된 제목만 검사에 반영 |
| `verify:m2:browser` | **15그룹 통과**, 실제 Chrome headless 360×800 |
| `verify:g2:secrets` | 브라우저 artifact 85개·개발 로그 1개·기존 HTML/API 응답 6개에서 실제 토큰 문자열 미검출 |
| 로컬 production HTTP | M2 화면 200, 제품 영화 API 503, 기존 G2 API 404 확인 |

브라우저에서는 설문→6부문 목록→후보 6장, 두 페이지 비중복/복원, pending 복원, 확정 후 이동, 건너뜀/미방문 구분, IME 이벤트·실제 한국어 검색 선택, 3부문 즉시 완료·복원, 확정작 변경, 제거 취소, 명시적 목록 복귀 시 pending 취소를 실행했다. 후보/목록 360px 가로 넘침도 0으로 확인했다.

브라우저의 이미지 error 이벤트, 검색 429/0건 응답은 **오류 주입 검사**다. 실제 검색·상세 성공과 구분해 [browser-checks.json](../artifacts/m2/browser-checks.json)에 기록했다. 검색 오류 시 확정작/후보 page 보존을 확인했다. 네트워크/timeout/인증 오류의 매핑은 기존 G2 오프라인 회귀 검사에 포함되며 실제 TMDB 장애 발생을 뜻하지 않는다.

## 미구현·미검증

특별상/심사평 계산·닉네임 입력·DB 저장·공개 결과·PNG 통합·CSV·실제 사용자 A/B 시험은 구현하지 않았다. G1 보안/SQL 및 G2/G3 기능 코드는 변경하지 않았다. 이번에는 Supabase 쓰기 실검증과 G3 PNG 전체 실검증을 재실행하지 않았다.

실제 iOS/Android 키보드, VoiceOver/TalkBack, Vercel 배포·다중 인스턴스 요청 보호, 친구 2~3명의 선택/레이아웃 비교는 미검증이다. IME 검사는 실제 Chrome에 composition 이벤트를 주입한 것으로 실제 한국어 OS 키보드 사용 검사를 대신하지 않는다. 브라우저 검사 클릭은 DOM/CDP로 실행했으며 손가락 오탭을 측정한 사용자 시험은 아니다. 로컬 초안은 평문이며 사용자 수정이 가능하므로 이후 DB 저장 단계는 ID·입력·결과를 서버에서 재검증해야 한다.
