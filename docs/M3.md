# M3 — 공식 수상 결과 HTML 로컬 미리보기

2026-10-21 · PRD/SCREEN_CONTENT/CODEX_STEPS v1.1 기반 사용자 요청. 이번 범위는 로컬 HTML이며 DB 저장·익명 인증 연결·공개 링크·PNG 통합은 하지 않는다.

## 확인 URL과 동선

`http://localhost:3000/create/result`

설문 → 3개 이상 부문 확정 → 시상식 열기 → 발표 전 확인의 ‘공식 결과지 미리보기’로 진입한다. 결과 페이지에서 설문/수상작을 고친 뒤 다시 확인 화면의 미리보기를 열면 갱신된다. 새로고침·랜딩의 이어쓰기에서도 결과 단계를 복원한다. 초안 없음/확정작 부족/지원하지 않는 입력은 안내와 복귀 링크를 표시한다.

## 결과 데이터와 규칙

`festival-result.ts`의 순수 함수가 버전·설문 값·3~6개의 고유 부문·영화 snapshot을 검증하고 부문 순서를 정규화한다. `previewFromDraft`는 확정작만 읽으며 pending/건너뛴 부문을 제외한다. 같은 영화의 복수 수상과 대상 없이 3부문을 허용한다.

결과 데이터는 정규화 survey/selections, ResultV11, 선정 부문 수·고유 영화 수, 내부 검증용 점수·선정 문장 코드로 구성된다. ResultV11의 evidence_ids는 실제 선택한 심사평/선정 문장 조건 코드다. 내부 점수·근거·설문 원문은 결과 화면에 표시하지 않는다. 이 데이터는 아직 서버 저장/공개 snapshot이 아니다.

q≥3인 응답만 `2*q+bonus`로 비교하고, 점수→높은 q→interpretation/audience/consensus/secret/credits 순서로 판정한다. 모두 null이면 sealed, 나머지 후보 없음은 chair다. 7종×3변형, P1~P6 선정 문장, 6개 관람량 문구를 SCREEN_CONTENT 원문과 일치시켰다. null이나 중간값을 행동 사실로 올리지 않는다.

결과는 캐시된 문구를 저장하지 않고 현재 초안에서 매번 다시 계산한다. 시간·난수·사용자 ID·draft_id·후보 배열·닉네임·CSV는 특별상/심사평 분기에 사용하지 않는다. 닉네임은 표제 표시만 바꾼다. 저장된 title·year·poster_path를 사용하고 TMDB에 새 메타데이터를 요청하지 않는다. 따라서 오래된 제목 snapshot을 임의로 바꾸지 않으며 운영 API 503 상태에도 이미 있는 초안 결과는 계산할 수 있다.

## 디자인·개인정보 경계

아이보리·버건디·한글 명조, 도록형 수상 목록, SVG 월계관·트로피·공식 도장을 사용했다. 포스터에는 장식 필터를 적용하지 않는다. 수상작 다음에 특별상·심사평·선정 문장을 배치하고 농담의 근거가 설문/시상이라는 안내를 표시한다. 긴 제목은 HTML에서 전체 표시하며 React 텍스트로 렌더링한다.

‘로컬 미리보기 · 미게시’, 서버에 저장·공개하지 않았다는 문구와 noindex를 적용했다. 서버가 내보내는 초기 HTML은 공통 로딩 화면이며 개인 초안은 브라우저에서 읽는다. 별도 결과 API/공개 URL/저장 버튼은 없다. 기존 G1/G2/G3 보안 코드와 운영 TMDB 게이트를 변경하지 않았다.

### 가상 사용자 기대값 비교

전체 출력은 [qa-results.json](../artifacts/m3/qa-results.json)에 기록했다. 기대값은 테스트에서 SCREEN_CONTENT 6.2를 별도로 파싱해 비교한다. Q01~Q12는 Chrome에서도 실제 렌더링한 심사평·선정문·관람량 문구를 비교했다. 12개 결과 생성 동안 결과/영화 API 호출이 없음을 확인했다.

브라우저에서는 초안 없음, 확정 2+pending 1의 거부, 결과 재로딩, M1 화면에서 q2를 4→2로 편집한 뒤 audience→chair 갱신, 실제 M2 카드로 확정작을 변경한 뒤 제목/선정문 갱신을 실행했다. 긴 제목·HTML처럼 보이는 문자열·없는 연도/포스터·이미지 error 이벤트·6부문 렌더링도 확인했다. 이미지 실패는 오류 주입이며 HTML 결과와 편집 동작은 유지됐다.

## 미구현·미검증

Supabase 게시·공개 공유 URL·PNG 통합·닉네임 입력·실제 사용자 유머 검증은 하지 않았다. 실제 iOS/Android/OS 키보드·VoiceOver/TalkBack·Vercel은 미검증이다. 자동 QA는 문구 계약을 확인하지만 재미·불쾌함·오해 여부를 증명하지 않는다. 특히 Q07/Q09의 문구 해석은 실제 사용자 확인이 남아 있다.

G1 실제 Supabase 쓰기와 G3 PNG 전체 실검증은 이번에 재실행하지 않았다. 기존 회귀 테스트는 통과했다. 로컬 저장소는 사용자가 변경할 수 있으므로 향후 서버 저장 단계에서는 영화 ID/입력/결과를 서버에서 다시 검증해야 한다. production 영화 검색의 관리형 보호는 여전히 미확인이고 503 게이트를 유지한다.
